🔑 Key Components

  • FSBPromotionHandlers: Handles 7 server events
  • FSBPromotionUIHandler: UI display logic and user interactions
  • FSBPromotionStore: Stores promotion data from server
  • FSBPromotionUIStore: Manages UI state and FSB state machine

🔄 Server Messages Flow

There are 7 types of server events handled by FSBPromotionHandlers. Each event has its own flow and triggers corresponding actions.

📨 7 Server Events

  • Promotion: Send new promotion data
  • PromotionTOProgress: Update turnover progress
  • ClaimedAmount: Confirm claim bonus success
  • RedeemResult: Redeem gift code result
  • FinishPromotion: End promotion
  • RedemptionNotice: Redemption error notice
  • ClaimedBonusFailed: Error when claiming bonus

🔄 Control Flow

  1. Server sends events → FSBPromotionHandlers
  2. Handlers update → FSBPromotionStore (data)
  3. Handlers call → FSBPromotionUIHandler (logic)
  4. UIHandler checks state from → FSBPromotionUIStore
  5. UIHandler adds UI event → pendingUIEvent in UIStore
  6. FSBPromotionUIManager observes → pendingUIEvent (MobX)
  7. UIManager renders → appropriate Component
  8. Components user actions → back to UIHandler
  9. UIHandler sends client messages → Server

⚙️ FSB State Machine

FSB has 5 main states: IDLE, READY, SPINNING, FINISHED, RESUMED. State is calculated dynamically based on flags in FSBPromotionUIStore.

graph LR Start([Start]) --> IDLE[IDLE] IDLE -->|Receive| READY[READY] READY -->|Consume| SPINNING[SPINNING] SPINNING -->|Commit| READY READY -->|Finish| FINISHED[FINISHED] SPINNING -->|Finish| FINISHED IDLE -->|Resume| RESUMED[RESUMED] RESUMED --> SPINNING RESUMED --> FINISHED FINISHED -->|Reset| IDLE

📊 State Conditions

  • IDLE: No promotion or not initialized
  • READY: Has promotion, currentSpinCount available, not spinning
  • SPINNING: Currently in FSB spin (fsbConsumedThisRound = true)
  • FINISHED: Server confirmed end of promotion
  • RESUMED: Resuming FSB promotion from previous session

🎰 Classic Slot Integration

FSB integrates with Classic Slot module similarly to Cascading. SlotBetHandler checks FSB state and uses FSB bet settings. Classic Slot has additional features like auto-spin continuation and Free Spin bonus interaction.

sequenceDiagram participant Player participant BetHandler as SlotBetHandler participant FSBUIStore as FSBPromotionUIStore participant FSBStore as FSBPromotionStore participant SettleHandler as SlotSettlementHandler participant FSBUIHandler as FSBPromotionUIHandler participant Server Player->>BetHandler: 1. Process Settlement SettleHandler->>SettleHandler: 11. checkToSpinNextFSB() SettleHandler->>FSBUIStore: 12. canSpinNextFSB? alt Can Continue FSBUIStore-->>SettleHandler: 13a. true SettleHandler->>FSBUIHandler: 14a. tryConsumeFSB() FSBUIHandler->>FSBUIStore: 15a. Decrease count FSBUIHandler->>FSBUIStore: 16a. Set consumed flag FSBUIHandler-->>SettleHandler: 17a. Success SettleHandler->>BetHandler: 18a. callBet() - Auto next FSB else Cannot SettleHandler->>SettleHandler: 13b. FSB finished end

🔗 Integration Points

  • SlotBetHandler: Checks isFSBPromotionInProgress, uses FSB betLevel when active
  • SlotSettlementHandler: Auto-continues FSB spins via checkToSpinNextFSB()
  • SlotUIHandler: Observes FSB pendingUIEvent and syncs slot state to isSpinningFSB
  • BetControlStore: Bet controls disabled during FSB, balance check skipped

⚠️ Key Differences from Cascading

  • Auto-Spin Continuation: Classic Slot auto-continues FSB spins after settlement
  • Free Spin Feature: FSB can trigger Free Spin bonus rounds, FSB pauses during Free Spins
  • State Sync: SlotUIHandler syncs slot state to FSB via MobX reactions
  • No Manual Consume: FSB is consumed automatically by settlement handler

🎮 Classic Slot Specific Features

  • Auto-Spin Integration: FSB works seamlessly with auto-spin, normal auto-spin counter pauses during FSB
  • Free Spin Priority: Free Spin bonus takes priority over FSB, FSB resumes after Free Spins complete
  • canSpinNextFSB: Computed property checks FSB active, has spins, not spinning, and not in Free Spin
  • State Synchronization: Real-time sync between SlotBoardStore.slotState and FSBPromotionUIStore.isSpinningFSB

🔑 Key Features

  • Real-time Progress: Updates automatically after each spin
  • Progress Bar: Visual indicator showing completion percentage
  • Claim Button: Enabled only when TurnOver requirement is met
  • Current/Required Display: Shows exact amounts (e.g., 500/1000)

📝 TurnOver Logic

  • turnoverRequired: Total TurnOver needed to claim bonus (from promotion data)
  • turnoverProgress: Current TurnOver accumulated (updated by server)
  • Server tracks TurnOver via PromotionTOProgress events
  • Claim button enabled when: turnoverProgress >= turnoverRequired
  • Panel remains visible throughout FSB promotion lifecycle

🎨 UI States

  • Initial: Progress at 0%, claim button disabled
  • In Progress: Progress bar animating, showing percentage
  • Complete: Progress at 100%, claim button enabled and highlighted
  • Claimed: Button disabled after successful claim

🔑 Dialog Components

  • FSBPromotionDialog: Main modal banner (shown once at start)
  • FSBPromotionInfo: Persistent info panel during gameplay
  • FSBWebView: Terms & Conditions viewer
  • FSBBottomMessage: Bottom bar notification

📝 Display Logic

  • First Time: Show dialog, wait for user acceptance
  • Resumed: Skip dialog, auto-transition to READY state
  • Dialog Content: Promotion name, spin count, bet settings, details button
  • Info Panel: Always visible during FSB gameplay, shows remaining spins

🎨 Dialog States

  • Hidden: Default state, not shown
  • Displayed: Modal shown, waiting for user action
  • Details Open: WebView overlay showing T&C
  • Accepted: Dialog dismissed, info panel visible during gameplay

🔄 State Transitions

  • IDLE → Dialog Show: When Promotion event received
  • Dialog Accept → READY: User accepts, can start spinning
  • READY → Info Panel: During FSB spins, show persistent info
  • FINISHED → Dialog Hide: Show end popup instead

📝 End Conditions
